# OPD 项目会议纪要（2026-08-14）

## 1. 会议主题

本次会议讨论了 Baseline 实验推进、Evolving Pipeline 设计、Loss 训练前评估，以及论文撰写安排。

## 2. Baseline 实验与 State 0

- 为建立 Evolving 的初始状态，需要先在项目统一 setting 下完成多个 Baseline 实验。
- Baseline 实验不仅提供 loss 实现，还需要提供完整的训练配置、训练过程和评测结果。
- 这些结果将构成后续 Evolving 可以读取的初始实验信息。
- 当前 State 0 的具体方法和实验要求见 [State 0 选择与复现实验计划](../plans/state-0-selection.md)。

### 当前问题

- EOPD 实验在训练过程中崩溃。
- 崩溃前观察到 reward 降为 0。
- 需要判断问题来自 loss 实现、数值稳定性、输入信号、训练配置，还是基础设施。
- 在 EOPD 问题排查期间，其他 Baseline 方法应并行推进，避免整体实验停滞。

## 3. Evolving Pipeline

Evolving Pipeline 不应只根据历史 loss 进行组合或局部修改。后续设计可以参考现有 Auto Research 系统，增加以下环节：

1. 对现有结果和失败原因进行分析；
2. 提出结构性假设；
3. 在条件允许时给出数学推导或理论解释；
4. 根据假设生成新的 loss；
5. 通过实验验证假设，而不仅是比较最终分数。

本次会议没有冻结最终的 Evolving Pipeline。当前优先级仍是完成 Baseline 实验并建立 State 0，之后再确定具体迭代方式。

## 4. Loss 训练前评估

当前部分 loss 结构较复杂，但缺少足够的理论依据和训练前验证。后续需要研究能否在正式训练前筛除明显无效或不稳定的 loss。

可以探索的方向包括：

- 为 loss 设计最小 test cases；
- 检查 loss 的数值范围、梯度方向和极端输入行为；
- 检查 loss 是否退化为 0、常数或与 Fixed OPD 等价；
- 使用论文中已有的分析指标作为先验检查；
- 判断 loss 的设计假设是否能够在 recorded batch 上被观察到。

训练前评估只能用于排除明显错误或退化的 loss，不能替代统一 setting 下的完整训练实验。

## 5. 论文撰写

- 讨论了 draft 的三种训练方式：`average`、`best` 和 `majority`。
- 当前实验显示三种方式各有优劣，但总体差异不大。
- 为简化论文和方法描述，最终只保留一种实现方式。
- 本次会议尚未确定最终保留哪一种，需要结合现有结果后做出选择。

## 6. 会议结论

1. 当前首先完成 Baseline 代码整理和完整实验，形成 State 0。
2. Evolving Pipeline 后续应包含结构性假设和必要的理论分析，而不只是组合已有 loss。
3. 需要研究训练前的 loss 检查方法，但完整训练仍是最终判断依据。
4. EOPD reward 降为 0 是当前需要优先定位的问题。
5. 论文中的 draft 训练方式最终只保留一种，以减少不必要的复杂度。
