# 基于检查点条件动作效用的自动在线策略蒸馏

## 定位说明

本计划是"OPD without regret · Learning-Utility Verifier"三层决策架构中的 **检查点层**。三层架构的完整视图为：

| 层级 | 决策问题 | 决策频率 |
|---|---|---|
| **Checkpoint-level（本计划）** | 本 epoch 采用哪套完整蒸馏方案 | 每 H 步一次 |
| Question-level | 当前阶段应采样哪些问题 | 每 batch 一次 |
| Token-level（M0） | 每个 token 使用哪个算子、什么权重 | 每 token 一次 |

**为什么从最粗粒度切入：** Token-level credit assignment 是三层中最困难的归因问题（batch reward 无法直接分配给单个 token）。Checkpoint-level 的反事实最易构造——完整模型与优化器状态可精确复制，分支之间的因果对比干净可审计。先验证粗粒度交互是否存在，再向细粒度推进，避免在 token 归因上投入大量计算后发现检查点间根本不存在动作偏好差异。

**与 Token-level M0 的接口：** 若 checkpoint-level 审计证实交互存在，token-level learned gate 可作为动作库的一个候选项（"本 epoch 使用 learned token gate" vs "本 epoch 使用 fixed RKL"），两层自然嵌套。

---

## 摘要

在线策略蒸馏（On-Policy Distillation, OPD）让学生模型在自身生成轨迹上接受教师分布监督。然而，学生在训练早期、中期和后期具有不同的能力与错误结构，同一蒸馏方案未必全程最优。

现有自适应方法依据教师熵、师生散度、轨迹质量等局部统计量，通过人工规则调整令牌权重或散度方向。它们尚未直接回答：

> 在当前学生检查点上，下一训练时期应当采用哪一种完整蒸馏方案，才能在等计算预算后留下最大的下游能力增益？

本研究将控制器步骤定义为一个检查点时期（$H=40$ 个优化器更新）。核心方法是：在审计检查点复制完整模型与优化器状态，执行不同训练动作的匹配分支，在相同总预算后比较独立审计能力，由此产生 **检查点条件动作效用标签**，再训练保守控制器——在无可信正收益时回退固定基线。

## 一、研究背景

### 1.1 在线策略蒸馏

设学生策略为 $\pi_{\theta}(y_t\mid x,y_{<t})$，教师策略为 $\pi_T(y_t\mid x,y_{<t})$。在线策略蒸馏首先由当前学生生成轨迹 $y\sim\pi_{\theta}(\cdot\mid x)$，然后在学生前缀上查询教师分布并更新参数。最常见的反向 KL 目标为：

$$
\mathcal{L}_{\mathrm{RKL}}(\theta)
= \mathbb{E}_{x,y}\left[\sum_{t=1}^{|y|}
D_{\mathrm{KL}}\!\left(\pi_{\theta}(\cdot\mid x,y_{<t})\;\|\;\pi_T(\cdot\mid x,y_{<t})\right)\right].
$$

### 1.2 固定方案的局限

训练各阶段存在系统性差异：

1. **早期**：师生差异大，教师在异常前缀上的监督可能不稳定；
2. **中期**：学生已掌握格式，需要能力迁移而非模式追逐；
3. **后期**：师生分布接近，过强监督可能降低多样性；
4. **贯穿全程**：局部损失下降不一定对应持续的下游能力增长。

[Rethinking OPD (Li et al., 2026)](https://arxiv.org/abs/2604.13016) 从机制层面揭示了这一困境的根源：OPD 成功的两个必要条件是 **(a) 师生思维模式兼容** 和 **(b) 教师具有学生尚未掌握的新颖能力**。随着训练推进，学生不断吸收教师能力，条件 (b) 逐渐耗尽；而不同蒸馏方案（如 RKL 促进模式追逐 vs FKL 维持覆盖）对条件 (a) 的敏感度不同。这意味着：

- 在教师新颖能力充足的阶段，强监督蒸馏方案（如 RKL + 高权重）可能最优；
- 在教师新颖性耗尽或思维模式不兼容的阶段，任何 OPD 都可能有害，应回退到 RL 或降低蒸馏强度；
- **最优方案随训练状态而变**——这正是本研究核心假设的机制性支撑。

### 1.3 现有自适应方法的共同结构

近期工作（熵感知散度切换、师生差异过滤、轨迹质量重加权、回合深度调节、局部置信度目标重构）均遵循：

$$
\text{局部统计量} \;\longrightarrow\; \text{人工制定的训练规则}.
$$

本研究关注另一层问题：

$$
\text{检查点状态} \;\longrightarrow\; \text{不同训练动作的未来效用} \;\longrightarrow\; \text{下一时期训练方案}.
$$

局部统计量仍有价值，但只作为控制器的 **输入特征**，而非直接的决策规则。

### 1.4 核心研究问题

1. 不同训练时期的最优 OPD 动作是否会稳定变化？
2. 局部代理量能否可靠预测训练动作的延迟下游效用？
3. 同检查点匹配分支是否比普通训练日志提供更有效的监督？
4. 能否在未见检查点上预测候选动作的相对排序？
5. 在等计算预算下，检查点条件控制器能否优于固定基线和全局最优固定动作？

### 1.5 核心假设

$$
\exists\,o_i,o_j,a_p,a_q:\quad
U(o_i,a_p)>U(o_i,a_q),\quad
U(o_j,a_p)<U(o_j,a_q).
$$

即训练状态与动作之间存在真实交互——同一动作不会在所有检查点上始终占优。若该假设不成立，自动控制器没有必要，应转向寻找更好的全局固定方案。

### 1.6 新颖性边界

本研究 **不** 主张首次将训练表述为 MDP、首次根据学生状态调整损失、首次用 RL 优化蒸馏、或首次发现不同 token 具有不同训练价值。

据当前检索，尚未有 OPD 工作同时实现：

1. 以完整蒸馏方案作为检查点级动作；
2. 从相同模型与优化器检查点执行多个匹配分支；
3. 在等预算、固定基线洗脱后测量延迟能力效用；
4. 学习检查点条件动作效用而非固定启发式；
5. 仅在预测收益具有可信正下界时偏离基线。

下面通过系统综述 2026 年 OPD 文献，确认这一缺口的存在并定位本研究在现有方法图谱中的位置。

## 二、相关工作

> **背景：** 截至 2026 年 7 月，OPD 已是 Qwen3、DeepSeek-V4、MiMo、GLM-5、Nemotron-Cascade 2 等系统的标准后训练组件。[awesome-on-policy-distillation](https://github.com/chrisliu298/awesome-on-policy-distillation) 收录 462 篇相关论文。下面按与本研究的关联度分类综述。

### 2.1 学习如何教学（概念先例）

- [Learning to Teach (2018)](https://arxiv.org/abs/1805.03643)：将学生训练表述为序贯决策，证明教学控制可用 RL 实现。
- [Dynamic Loss Functions (2018)](https://arxiv.org/abs/1810.12081)：根据训练阶段生成动态损失。
- [Learning from Student Feedback (2021)](https://arxiv.org/abs/2109.04641)：用学生反馈调整教师。

这些是概念先例，但未研究 LLM OPD，未把不同蒸馏方案作为检查点级动作，更未通过同检查点分支产生效用标签。

### 2.2 训练阶段/调度感知的 OPD（2026，最相关）

以下工作已具有"根据训练动态调整蒸馏行为"的特征，是本研究最直接的对比对象：

| 方法 | 核心机制 | 与本研究的差异 |
|---|---|---|
| [**ATESD** (2026)](https://arxiv.org/abs/2605.11458) | 将教师暴露比例视为可学习控制变量，通过 Beta-policy 控制器和折扣学习进度奖励调整 | 控制 1D 连续标量（暴露比例），非完整蒸馏方案选择；无同检查点匹配分支 |
| [**ADWIN** (2026)](https://arxiv.org/abs/2605.28396) | 用延迟全 rollout 探针审计前缀—全程梯度对齐度，在线调整 OPD 训练窗口长度 | 有"审计"概念，但审计对象是窗口长度而非蒸馏方案；规则性调整 |
| [**DRIFT** (2026)](https://arxiv.org/abs/2606.30345) | 按跟踪的学习进度将自蒸馏与 RL 信号按问题分配 | 根据进度路由 OPD vs RL，但在 per-problem 级别而非 checkpoint 级别 |
| [**NPO / AutoNPO** (2026)](https://arxiv.org/abs/2604.20733) | 用同策略的更晚检查点作教师，AutoNPO 自适应触发教师切换以最大化 RLVR 信号 | 检查点级教师切换决策，但动作空间仅为"何时更新教师"而非"用哪种蒸馏方案" |
| [**When Should the Teacher Move?** (2026)](https://arxiv.org/abs/2606.03532) | 基于巩固证据（consolidation evidence）门控历史教师刷新，替代时钟驱动更新 | 同属训练时序决策，但只控制教师更新时机而非蒸馏算法选择 |
| [**ATOD** (2026)](https://arxiv.org/abs/2606.27814) | 从 OPD 向 RL 退火混合优势，让多轮 agent 先模仿后超越教师上限 | 有阶段退火，但退火曲线为预设的人工调度 |
| [**CADENCE** (2026)](https://arxiv.org/abs/2607.16955) | 根据学生对教师 token 的覆盖率门控 FKL→RKL 的 per-token 混合，而非按时间 | 覆盖率驱动而非时间驱动，但仍是令牌级固定规则 |

**关键观察：** ATESD 是目前最接近的工作——它首次在 OPD 中引入"学习控制变量"的范式。然而 ATESD 控制的是单一连续标量（教师暴露比例），使用即时学习进度奖励，且未通过同检查点反事实分支验证延迟效用。本研究将动作空间扩展为离散的完整蒸馏方案集合，并引入匹配分支协议获取延迟效用标签。

### 2.3 令牌级自适应 OPD（2026）

这些工作在令牌粒度上做自适应，是本研究动作库中各方案的内部实现：

| 方法 | 决策单位 | 核心机制 |
|---|---|---|
| [**TIP** (2026)](https://arxiv.org/abs/2604.14084) | 令牌 | 选择性训练高熵和自信错误的低熵 token |
| [**FiRe-OPD** (2026)](https://arxiv.org/abs/2606.02684) | 轨迹+令牌 | 先按教师似然过滤轨迹，再按教师置信度和学生困惑度重加权 token |
| [**SCOPE** (2026)](https://arxiv.org/abs/2604.10688) | 令牌 | 正确 rollout 走学生 PPL 加权 MLE，错误 rollout 走教师 PPL 加权 KL |
| [**Reward-Gated OPD** (2026)](https://arxiv.org/abs/2607.04037) | rollout | 用验证器奖励符号与师生似然差的一致性门控教师信号 |
| [**Trust Region OPD** (2026)](https://arxiv.org/abs/2606.01249) | 令牌区域 | 在教师可靠区域用 RKL，异常区域用 FKL/掩码 |
| [**Veto** (2026)](https://arxiv.org/abs/2601.07155) | 令牌 | logit 空间中间目标分布稳定训练 |
| [**SG-OPD** (2026)](https://arxiv.org/abs/2606.09304) | 令牌 | 二值验证器与教师的符号一致性路由蒸馏方向 |
| [**Blockwise Policy-Drift Gating** (2026)](https://arxiv.org/abs/2606.24084) | 块 | 学生块级策略漂移门控位置损失权重 |
| [**Decision-Supporting Tokens** (2026)](https://arxiv.org/abs/2606.22830) | 令牌 | 学生熵 + 隐状态相似度 + 师生散度发现决策 token |
| [**Position Bias / IW-OPD** (2026)](https://arxiv.org/abs/2606.22600) | 令牌 | 按累积前缀师生偏差的重要性加权修正位置偏差 |

这些方法各自可成为本研究动作库的一个候选方案。它们在"当前 token 是否适合蒸馏"上做优化，但未回答"当前检查点应该使用哪一种 token 处理方案"。

### 2.4 实证分析与失败模式（2026）

| 方法 | 发现 |
|---|---|
| [**Rethinking OPD: Phenomenology, Mechanism, and Recipe** (2026)](https://arxiv.org/abs/2604.13016) | OPD 成功的关键驱动因素是兼容的思维模式和教师具有学生尚未掌握的新颖能力；不满足这些条件时 OPD 可能无效甚至有害 |
| [**Revisiting OPD** (2026)](https://arxiv.org/abs/2603.25562) | 截断 RKL + teacher top-K support matching 修复信号不平衡和分词器不匹配 |
| [**Dense Supervision, Sparse Updates** (2026)](https://arxiv.org/abs/2606.13657) | OPD 检查点增量呈稀疏、off-principal 编辑，类似 RLVR 而非稠密监督学习 |
| [**Prefix Teach, Suffix Fade** (2026)](https://arxiv.org/abs/2605.13643) | strong→weak OPD 中教师局部 margin 在后缀坍缩，需动态释放规则截断 |
| [**Thinking Collapse in OPSD** (2026)](https://arxiv.org/abs/2607.10805) | 自蒸馏中推理 token 被不对称抑制，需冻结基线参考先验锚定 |

这些分析为动作库设计和控制器决策提供了直接的实证依据：

- **Rethinking OPD** 指出 OPD 的成功条件（思维模式兼容性 + 教师新颖能力）在训练过程中持续变化——这为"动作排序随检查点变化"提供了机制性解释。当教师新颖性耗尽时，所有 OPD 方案的效用都应趋近于零甚至为负，此时保守控制器的正确行为是回退基线或降低蒸馏强度。
- **Dense Supervision, Sparse Updates** 表明 OPD 实际产生的是类 RLVR 的稀疏编辑而非稠密覆写——这暗示不同 OPD 方案的差异可能比表面损失差异更微妙，需要延迟下游评价而非即时代理量来区分。
- **Prefix Teach, Suffix Fade** 和 **Thinking Collapse** 各自揭示了特定训练阶段的失败模式——这些失败模式对应的修复方案（动态截断、参考先验锚定）正是动作库的候选条目。

综合来看，2026 年的实证分析工作为本研究提供了两层支持：(1) 理论层面，OPD 有效性条件随训练推进而变化，支持检查点条件决策的必要性；(2) 工程层面，已有修复方案各有适用阶段，为构建有意义的动作库提供了素材。但这些工作未研究如何在线判断当前应激活哪种修复方案——这正是本研究试图填补的缺口。

| 方法 | 核心机制 |

### 2.8 尚未解决的缺口

$$
\underbrace{z_{i,t}\longrightarrow w_{i,t}}_{\text{令牌内部自适应（2026 主流）}}
\quad\neq\quad
\underbrace{o_n\longrightarrow a_n\longrightarrow U(o_n,a_n)}_{\text{检查点级动作选择（本研究）}}
$$

2026 年 OPD 领域的主要进展集中在令牌级精细化（如何更好地加权或路由单个 token）。ATESD 首次引入了"学习控制变量"范式，但仅控制一个连续标量且使用即时奖励。本研究在三个维度上推进：(1) 动作空间从标量扩展到离散方案集合；(2) 效用度量从即时进度信号转为匹配分支后的延迟能力；(3) 引入保守机制避免在不确定状态下损害训练。

基于上述文献定位，下面给出具体的方法设计。

## 三、方法

### 3.1 决策时间尺度

- $t$：优化器更新索引
- $n$：控制器时期索引，$t_n = nH$

控制器在 $t_n$ 时选择动作 $a_n$，在区间 $[t_n, t_n+H)$ 内持续执行。首版固定 $H=40$。

### 3.2 检查点状态

模型—优化器检查点：

$$
x_n = (\theta_{t_n},\, \omega_{t_n}).
$$

控制器读取压缩观测 $o_n = g_\psi(s_n)$，首版包括：

1. 训练进度与剩余预算
2. 近期训练损失及变化率
3. 梯度范数、参数更新范数、裁剪比例
4. 教师熵、学生熵、师生 KL 的分位数
5. 轨迹长度、截断比例、答案可验证率
6. 最近动作及其持续时期数
7. 已完成审计的动作效用与不确定性

### 3.3 动作集合

$$
\mathcal{A} = \{a^{(0)}, a^{(1)}, \ldots, a^{(K-1)}\}.
$$

首版单轮推理任务的动作库：

| 动作 | 方案 | 作用 |
|---|---|---|
| $a^{(0)}$ | 固定 RKL OPD | 安全基线 |
| $a^{(1)}$ | 熵感知 OPD | 高教师熵区域增强分布覆盖 |
| $a^{(2)}$ | 轨迹过滤 + 令牌重加权 | 降低低质量轨迹影响 |
| $a^{(3)}$ | 自适应目标重构 | 抑制低置信区域的有害梯度 |

每个动作内部可定义令牌权重 $w_{i,t} = h_{a_n}(z_{i,t})$，但不对 $w_{i,t}$ 做因果归因。

### 3.4 受约束训练目标

$$
\max_{\mu}\;\mathbb{E}_\mu\bigl[J_{\mathrm{test}}(\theta_{t_N})\bigr]
\quad\text{s.t.}\quad C \le C_{\max}.
$$

不使用能力—成本—风险的任意线性加权（缺乏可信兑换率）。首版固定教师调用次数、生成令牌数、优化器更新数和评价次数，使比较不依赖人为系数。

### 3.5 同检查点匹配分支

**审计时机：** 每隔 $I$ 个时期选择审计根（首轮暂取 $I=10$）。

**共同根：** 精确复制模型参数、优化器状态、学习率调度器、数据迭代器位置、随机数生成器、教师版本和代码版本。

**动作窗口 + 固定基线洗脱：**

$$
x_{n,B}^{a,r} = \mathcal{U}_{\pi_0}^{B-H}\!\left(\mathcal{U}_a^H(x_n;\xi_{n,r});\,\zeta_{n,a,r}\right).
$$

纯基线分支：

$$
x_{n,B}^{0,r} = \mathcal{U}_{\pi_0}^B(x_n;\xi_{n,r}).
$$

基线洗脱区分短期更新幅度与持续能力增益：若某动作只产生大梯度但回到基线后优势消失，其延迟效用应接近零。

**随机性匹配：** 前缀相同时共享问题顺序与随机数；前缀分化后切换到分支局部随机流。禁止不同分支复用不一致前缀的教师缓存。

### 3.6 动作延迟效用

$$
Y_{n,r}(a) = J_{\mathrm{audit}}(x_{n,B}^{a,r}) - J_{\mathrm{audit}}(x_{n,B}^{0,r}).
$$

同一审计根平均效用：

$$
\overline{Y}_n(a) = \frac{1}{R}\sum_{r=1}^R Y_{n,r}(a).
$$

需要学习的目标：

$$
U(o,a) = \mathbb{E}\bigl[Y_n(a)\mid O_n = o\bigr].
$$

这不是单令牌效用，而是相对于固定基线、在可观测检查点状态条件下的训练动作效用。

### 3.7 动作效用预测器

训练数据：$\mathcal{Z} = \{(o_n, a, \overline{Y}_n(a)) : n\in\mathcal{I}_{\mathrm{audit}},\, a\in\mathcal{A}\}$。

首版优先训练动作排序（成对排序损失）：

$$
\mathcal{L}_{\mathrm{rank}} = -\log\sigma\!\left(f_\phi(o_n, a_i) - f_\phi(o_n, a_j)\right),
\quad\text{where}\;\overline{Y}_n(a_i) > \overline{Y}_n(a_j).
$$

训练与验证按检查点及时间分块，不随机拆分同一检查点的记录。

### 3.8 不确定性与保守选择

训练 $E$ 个不同初始化的预测器。集成均值与方差：

$$
\widehat{U}_n(a) = \frac{1}{E}\sum_{e=1}^E f_{\phi_e}(o_n,a),
\qquad
\widehat{\sigma}_n^2(a) = \frac{1}{E-1}\sum_{e=1}^E\bigl[f_{\phi_e}(o_n,a) - \widehat{U}_n(a)\bigr]^2.
$$

置信下界：

$$
\mathrm{LCB}_n(a) = \widehat{U}_n(a) - \beta\,\widehat{\sigma}_n(a).
$$

保守控制器：

$$
a_n = \begin{cases}
\arg\max_{a\in\mathcal{A}}\mathrm{LCB}_n(a), & \max_{a}\mathrm{LCB}_n(a) > \varepsilon,\\
a^{(0)}, & \text{otherwise}.
\end{cases}
$$

"保守"是经验操作定义，不构成理论安全或无遗憾保证。

### 3.9 完整训练流程

1. 从固定基线 $a^{(0)}$ 开始训练；
2. 每 $H$ 步形成新检查点观测；
3. 每 $I$ 个时期执行完整匹配分支审计；
4. 积累 $M_{\min}$ 个审计根前始终执行基线；
5. 达到最小审计数后训练效用预测器；
6. 非审计时期使用保守控制器选择动作；
7. 新审计完成后增量更新预测器；
8. 最终模型冻结后只访问一次锁定测试集。

### 3.10 数据隔离

| 数据部分 | 用途 | 禁止用途 |
|---|---|---|
| 训练问题集 | 学生生成与参数更新 | 最终能力主张 |
| 动作效用审计集 | 计算 $Y_{n,r}(a)$ | 选择最终检查点 |
| 控制器验证集 | 选择 $\beta$、$\varepsilon$ 和模型结构 | 训练效用标签 |
| 锁定测试集 | 所有方法冻结后评价一次 | 训练、审计、早停、阈值选择 |

### 3.11 可识别性条件

1. 所有分支从完全相同的模型与优化器状态出发
2. 相同问题块与可匹配随机性
3. 动作执行顺序与硬件分配随机化
4. 分支间无缓存/显存/调度干扰
5. 从共同根到终端使用相同计算预算 $B$
6. 相同评价程序
7. 预测器只使用动作执行前可见信息
8. 每个候选动作在足够多检查点上被审计
9. 审计集、验证集、测试集相互隔离

## 四、实验设计

### 4.1 三阶段路线

| 阶段 | 目标 | 进入条件 |
|---|---|---|
| 一 | 验证状态—动作交互存在 | — |
| 二 | 验证动作效用可在未见检查点预测 | 阶段一通过 |
| 三 | 验证保守在线控制优于固定方案 | 阶段二通过 |

### 4.2 实验假设

**H1（动作排序随状态变化）：**
$$
\exists\,n_i,n_j,a_p,a_q:\quad
\overline{Y}_{n_i}(a_p) > \overline{Y}_{n_i}(a_q),\quad
\overline{Y}_{n_j}(a_p) < \overline{Y}_{n_j}(a_q).
$$

**H2（状态具有增量预测价值）：**
$$
\mathrm{Err}(f_{\mathrm{state+action}}) < \mathrm{Err}(f_{\mathrm{action\text{-}only}}).
$$

**H3（匹配分支具有增量监督价值）：**
$$
\mathrm{Err}(f_{\mathrm{fork}}) < \mathrm{Err}(f_{\mathrm{log}}).
$$

**H4（保守控制降低负迁移）：**
$$
\Pr(Y_n(a_n) < 0) < \Pr(Y_n(a_n^{\mathrm{greedy}}) < 0).
$$

**H5（自动控制提高等预算最终能力）：**
$$
\mathbb{E}\bigl[J_{\mathrm{test}}(\theta_N^\mu)\bigr] > \max_{a\in\mathcal{A}}\mathbb{E}\bigl[J_{\mathrm{test}}(\theta_N^a)\bigr].
$$

### 4.3 第一阶段：状态—动作交互审计

**设计：**
- 早、中、后期各选多个独立检查点根
- 四个候选动作，$H=40$
- 两个候选洗脱预算 $B\in\{120, 200\}$（预实验后固定一个）
- 每个检查点—动作组合多个匹配重复

**统计模型：**
$$
Y_{k,r,a} = \mu + \alpha_k + \beta_a + \gamma_{k,a} + u_r + \epsilon_{k,r,a}.
$$

重点检验交互项 $\gamma_{k,a}$ 是否显著且量级大于审计噪声。

**进入下一阶段的条件：**
1. 不同阶段出现可重复的动作排序变化
2. 交互效应大于审计噪声
3. oracle显著优于全局最优固定动作
4. 结论跨不同 $B$ 和重复保持方向一致

### 4.4 第二阶段：离线动作效用预测

**划分：** 按时间分块——较早检查点训练、中间验证、更晚测试。

**比较模型：**
1. 状态—动作预测器（完整）
2. 只看动作编号的平均效用模型
3. 只看损失和熵的线性模型
4. 普通训练日志回归模型
5. 标签置换模型（证伪基线）
6. 不使用历史序列的静态模型

**成功标准：** 未见检查点排序准确率 > action-only 模型；正负号准确率显著高于随机；标签置换后降至随机。

### 4.5 第三阶段：保守在线控制

**比较方法（所有方法严格匹配计算预算）：**

| 类别 | 方法 |
|---|---|
| 固定基线 | 固定 RKL OPD；每种候选动作的全程版本；全局最优固定动作 |
| 控制器基线 | 随机控制器；循环控制器；贪心控制器（无不确定性回退） |
| 本方法 | 保守控制器（LCB + 基线回退） |
| 诊断上界 | oracle（事后选择最佳动作） |
| 证伪 | 标签置换后训练的控制器 |

**匹配条件：** 模型初始化、问题顺序、总更新数、总生成量、教师调用数、GPU 时数、评价次数、独立种子数。

### 4.6 消融实验

1. 删除基线洗脱（只测 $H$ 步后短期能力）
2. 不匹配优化器状态
3. 不匹配问题顺序与随机性
4. 删除训练历史，只保留当前统计
5. 删除令牌/轨迹统计，只保留训练进度
6. 删除预测不确定性
7. 删除基线回退
8. 跨检查点标签置换
9. 用日志代理量替代分支效用
10. 变化 $H$ 和 $B$
11. 减少动作数量

### 4.7 评价指标

**最终能力：**
$$
\Delta J_{\mathrm{test}} = J_{\mathrm{test}}(\theta_N^\mu) - J_{\mathrm{test}}(\theta_N^{\pi_0}).
$$

**排序质量：** 第一名准确率、成对排序准确率、正负号准确率、等级相关。

**不确定性质量：** 覆盖率、校准误差、回退比例、负效用比例。

**经验遗憾（仅审计根上定义）：**
$$
\mathcal{R}_{\mathrm{emp}} = \sum_{n\in\mathcal{I}_{\mathrm{audit}}}\bigl[\max_a \overline{Y}_n(a) - \overline{Y}_n(\widehat{a}_n)\bigr].
$$

**效率：** 单位 GPU 时数能力、达到阈值所需成本、能力—计算曲线下面积。

### 4.8 统计检验规范

- 配对比较（相同初始化与数据顺序）
- 多种子均值、标准误、置信区间
- 按检查点分组（不把同检查点分支当独立样本）
- 多重比较校正
- 预先登记主要指标、停止条件和排除规则
- 同时报告效应量和不确定性

### 4.9 计算预算

$$
C_{\mathrm{audit}} \approx M(K+1)RB\,C_{\mathrm{step}}.
$$

降低成本优先顺序：减审计根数 > 减动作数 > 分阶段淘汰劣势动作 > 减重复数（重复数过少直接损害标签可信度）。

### 4.10 停止条件

出现以下任一情况应停止扩大实验：

1. 动作排序跨检查点基本不变
2. oracle不优于全局最优固定动作
3. 状态—动作预测器不优于 action-only 模型
4. 标签置换后性能无明显下降
5. 日志模型与分支模型表现相同
6. 动作效应小于评价噪声
7. 控制器只在已见检查点有效
8. 收益完全可由更新范数或有效令牌数解释
9. 保守控制器不优于全局最优固定动作
10. 审计集收益与测试集收益方向不一致

## 五、预期结论

### 5.1 若核心假设成立

> 在线策略蒸馏不存在对所有训练阶段都占优的单一方案。通过同检查点、等预算训练分支可构造具有可审计性的阶段动作效用标签；基于这些标签学习的检查点条件控制器能在未见状态上选择更合适的方案，并在置信不足时安全回退。

### 5.2 不能直接形成的结论

- 单令牌训练贡献被准确识别（本研究不做 token 归因）
- 控制器具有理论无遗憾保证
- 置信下界构成严格安全保证
- 一个任务上的规律可无条件迁移
- 检查点观测包含影响效用的全部潜在状态

### 5.3 可能的否定性结论

- **动作排序不变**：在当前动作集合与学生规模下，无证据表明条件选择优于固定方案。
- **可预测但不可外推**：效应存在但状态观测不足以支持在线选择。
- **日志足够**：昂贵分支不是必要条件，应改用低成本日志控制器。

每种否定性结论同样有发表价值，且会明确指向下一步研究方向。

## 六、主要风险与控制

| 风险 | 后果 | 控制措施 |
|---|---|---|
| 只复制模型未复制优化器 | 分支起点不一致 | 保存完整优化器张量与计数器 |
| 分化后共享教师缓存 | 教师条件分布错误 | 完整前缀哈希 + 分支命名空间 |
| 动作更新幅度差异过大 | 大梯度动作虚假占优 | 匹配预算并报告更新范数 |
| 同检查点记录随机拆分 | 状态泄漏 | 按检查点和时间分块 |
| 审计集兼作测试集 | 测试适应 | 四层数据隔离 |
| 评价噪声 > 动作效应 | 标签不可学习 | 增加重复、扩大 $B$、改变动作集 |

## 七、执行顺序

| 优先级 | 任务 | 判定 |
|---|---|---|
| **P0** | 实现统一动作接口 + 完整检查点复制 | 基础设施 |
| **P1** | 小规模匹配分支审计（3 阶段 × 4 动作） | 回答"oracle是否稳定优于全局最优固定动作" |
| **P2** | 若交互成立，扩大审计根并训练离线排序模型 | 回答"能否预测" |
| **P3** | 若预测成立，运行保守在线控制完整实验 | 回答"能否控制" |
| **P4** | 扩展至不同学生规模、任务类型、多回合环境 | 泛化性 |

**当前最优先回答的问题：**

$$
\boxed{\text{oracle是否稳定优于全局最优固定动作？}}
$$

只有答案为肯定时，检查点条件自动 OPD 才具有充分的实证研究价值。
