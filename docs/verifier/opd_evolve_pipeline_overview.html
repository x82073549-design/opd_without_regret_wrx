01 · Executive summary

现在不是缺少新想法，而是缺少一个能正确判断想法的系统。

现有 pipeline 已经证明 LLM 可以生成结构化 loss，并能通过多层验证进入真实训练；但工程状态、机制验收、短预算评价和最终 selection metric 仍存在断层。继续增加 feature 之前，应先修复这些断层。

WHAT WORKED

温和 routing

唯一稳定正收益候选保留 Fixed OPD 的 support direction，只对可靠 disagreement token 做有界 credit reallocation。

WHAT FAILED

激进替换与极端稀疏

Union support 两次被同一 device bug 阻断；outcome switch 将约 90% token 置零，再被 scale matching 放大约 11.86 倍。

WHAT NEXT

先修“判断器”

补齐源码与 lineage，增加机制活性门槛，按 action family 分配多保真预算，再开展 teacher confidence × student entropy 联合门控。

!

核心判断

当前系统可视为 “搜索原型已跑通，但尚未达到研究级可审计闭环”。训练底座、评测护栏和候选安全接口已经具备；真正缺的是源码同步、failure taxonomy、机制活性测试、多保真筛选和目标一致的 winner selection。

02 · System boundary

当前仓库中，训练链是真实代码；evolve 链主要存在于实验记录。

这是理解现状的第一条边界。两条链路不能因为共享 OPD loss 而被视为同一个软件系统。

Available in main

可执行 OPD 训练与评测底座

  • 2-GPU / 8-GPU 训练入口与 Hydra 配置
  • student rollout、teacher top-k/log-prob/entropy
  • Fixed OPD、sampled/top-k gate、overlap route 等机制
  • checkpoint merge、generation、grading、paired report
  • manifest、seed、数据去重和运行目录隔离护栏
Absent from main

文档引用但未提交的搜索执行器

  • opd_loss_search/search.py 与 coordinator
  • tensor contract、SafeOps、candidate validator
  • 每轮候选 loss.py、state、champion 和 history
  • recorded action batches 与完整 failure traces
  • probe / confirmation 的 resolved manifests
P0

优化前置条件

首先把搜索源码、运行配置、候选文件和最小可复现实验同步进独立分支。否则我们只能优化“复盘文档中的系统”，无法验证优化是否改变真实行为。

FEATURE LIFECYCLE

Student entropy 过早释放

Student entropy 已在 actor forward 中产生，但当前主要用于日志，进入统一 token feature weighting 之前就被移除。

COUPLING

多个 action 混在 reward worker

Support 构建、divergence、route、gate 和部分 fallback 混在一个大函数中，使 candidate contract、组合测试和 device 管理变得困难。

EXCLUSIVITY

机制组合由互斥条件控制

sampled gate、top-k gate、overlap route、ratio switch、oracle gate 等存在大量成对互斥，难以系统搜索组合结构。

05 · Candidate contract

Candidate 不直接控制训练；它只提出受限 action。

这个边界应保留，并进一步升级成版本化、device-safe、可组合的稳定 ABI。

Δ

Magnitude matching 的双刃剑

它能阻止候选仅靠增大整体梯度“作弊”，但也会把稀疏 action 放大到危险尺度。未来不能只匹配 mean absolute advantage，还需同时约束 active ratio、max token gradient mass、scale cap 与 group-wise concentration。

06 · Four-round evidence

四轮搜索揭示的不是“哪个 feature 最好”，而是什么样的结构更可学习。

ROUND 000Reliable Disagreement Router

保留 Fixed OPD support direction，用 teacher reliability、JSD、student overconfidence 与 tail stability 做有界 token credit reallocation。机制活跃、ESS 健康，成为 champion。

+0.729 pp100-step confirmation
ROUND 001First Error Onset Credit

累计 hazard 在长响应中快速饱和，约 96.5% token priority 变为 0；经过均值归一化后几乎退化为 uniform Fixed OPD。

−0.729 pp100-step confirmation
ROUND 002Fixed Pareto Consensus Bridge

在 Fixed OPD 上叠加零和 support residual。10-step 明显负，但 100-step 两个 seed 均小幅正，直接证明统一短 probe 会误判 action family。

+0.417 ppprobe 为 −5.000 pp
ROUND 003Outcome-safe Reliable Switch

约 90% token 被 neutralize，runtime 将剩余 action 放大 11.86 倍；两个 training seed 方向相反，说明稀疏 gate 与 scale matching 存在交互风险。

−0.208 ppseed directions disagree
→

从四轮结果得到的搜索 prior

优先搜索“保留稳定 base objective + 有界残差/路由”，而不是直接替换完整 support objective 或执行大比例 hard kill。激进 action 仍可探索，但必须进入独立的风险预算与更长 probe。

08 · Target architecture

把 evolve 从“生成 loss 的脚本”升级为六层研究系统

核心设计原则是：feature、action、验证、搜索、实验和 memory 分层，每层都输出可冻结、可 hash、可重放的 artifact。

01 · Feature Planefeature contract
集中生产 teacher/student distribution features、outcome、region、history 与 support statistics；定义 shape、mask、device、stop-gradient 和版本。
FeatureBundle + availability manifest
02 · Action Runtimecandidate ABI
Candidate 只选择 support objective、bounded residual、token gate/weight 与 active mask；runtime 负责 canonicalization、projection、fallback 和 scale policy。
ActionOutput + mechanism metrics
03 · Validation Gatemechanism-aware
除 schema、AST、finite 之外，检查 action 是否真的区别于 parent、是否过稀疏、是否依赖缺失输入、是否触发异常 scale 或 device transfer。
typed verdict + failure class
04 · Search Controllermulti-fidelity
先生成假设，再独立 rank；依据 action family、uncertainty、novelty 和基础设施风险分配 smoke、probe 与 confirmation 预算。
candidate queue + budget policy
05 · Experiment & Evalmatched evidence
Matched baseline、training seeds、evaluation seeds、manifest 和逐题配对统计；primary metric 在搜索前冻结。
paired evidence package
06 · Research Memoryappend-only
保存设计动机、parent、代码 hash、机制状态、失败阶段、uncertainty 与下一步建议；同一批候选读取同一 snapshot。
versioned memory snapshot

可复现

任一 champion 都能从 commit、manifest、candidate hash 和 seed 重新执行。

机制活跃

候选不仅 finite，还必须证明预期 gate、residual 或 support change 真正发生。

预算匹配

不同 action family 采用不同 horizon；不让短期 proxy 垄断长期研究决策。

目标一致

搜索、early stop、champion selection 和最终论文指标使用同一预注册语义。

09 · Multi-feature gating

Teacher confidence × Student entropy：先做可证伪联合门控，不直接上黑盒 MLP。

单 feature 不显著并不等价于联合信号无效。合理假设是：teacher confidence 表示监督可靠性，student entropy 表示学生不确定性；只有二者组合才定义“值得学且可学”的区域。

G1 · ADDITIVE

可解释线性门控

g = sigmoid(a·z(conf_T) + b·z(ent_S) + c)

先回答两个 feature 是否提供互补排序；参数少，易做 sign flip、shuffle 和 calibration。

G2 · INTERACTION

显式交互门控

g = sigmoid(a·z(conf_T) + b·z(ent_S) + d·z(conf_T)·z(ent_S) + c)

直接检验“高可靠 teacher × 高不确定 student”是否是独立于两个主效应的有效区域。

G3 · SAFE RESIDUAL

保留 Fixed OPD 的残差式 routing

w = 1 + λ·bounded_priority(conf_T, ent_S)

延续当前 champion 的成功 prior：不改变 base support direction，只在受控范围内重分配 credit。

建议最小实验矩阵

B0
Fixed OPD同 seed、同起点、同总梯度预算。
B1
Teacher confidence only复现单 feature 结论，作为联合增益的 matched control。
B2
Student entropy only明确方向并验证 feature lifecycle 正确。
J1
Additive joint gate主效应组合，不含 interaction。
J2
Interaction joint gate检验联合区域是否带来额外收益。
N1
Shuffled / mismatched controls保持边际分布与总权重，只破坏 token 对齐。
✓

联合门控的通过标准

联合方法应同时满足：优于最强单 feature；相对 shuffled control 有稳定差异；两个 training seeds 方向一致；gate 不塌缩为常数或极端 0/1；mean weight、active token budget 和 pre-clip gradient mass 与 baseline 可比。

10 · Optimization roadmap

建议按“恢复—校验—重构—搜索—扩展”推进

PHASE 0

恢复可复现状态

同步 search 源码、历史 candidates、state、manifest 和最小 recorded batch；复现 champion identity。

出口：一条命令重放 round 000
PHASE 1

补机制验收

加入 active ratio、gate variance、support delta、scale cap、gradient concentration 和 failure taxonomy。

出口：退化 candidate 在 GPU probe 前被识别
PHASE 2

分层 action runtime

建立 FeatureBundle、support adapter、objective、normalizer 与 diagnostics 的稳定边界。

出口：joint gate 与 union support 可独立测试
PHASE 3

升级搜索策略

独立 hypothesis ranker、action-family-aware horizon、sequential racing 和目标一致 selection。

出口：预算去向可解释、可复盘
PHASE 4

联合 feature 实验

先 additive / interaction / safe residual，再决定是否需要小型 learned gate。

出口：明确联合信号是否真实存在
≠

暂不建议

暂不建议直接把所有 feature 输入 MLP、直接启用 forward kill、或让 Codex 同时修改 optimizer/rollout/evaluation。当前独立实验数量不足以支撑黑盒 gate，且会让收益无法归因。

11 · Decision gates

每一阶段都应有明确的继续与停止条件

GATE A

Reproducibility：Fixed OPD identity、champion hash、recorded replay 与 1-step GPU smoke 可重放。

失败 → 不开始新搜索
GATE B

Mechanism activity：候选与 parent 存在实质 diff，且 gate/residual/support 统计落在预注册健康范围。

失败 → repair 或淘汰
GATE C

Proxy validity：该 action family 的短预算排序能预测更长 horizon，或 uncertainty 足以支持继续 racing。

失败 → 延长 probe / 改 proxy
GATE D

Research evidence：matched seeds、paired CI、负对照和机制解释共同支持收益。

失败 → 不写入 champion 结论
